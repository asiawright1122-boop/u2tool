# SEO 第四阶段：发布前验收与重点工具功能抽查

日期：2026-10-09。所有修复只在本地；没有提交、推送、部署、向 GSC/Bing 提交 URL 或调整账号设置。没有更改索引抑制集合、sitemap 日期或用户原有内容信任审计文档。

## 本轮发现与处理

### 1. 取色器输出停留在初始颜色（已修复）

真实 Cloudflare 构建的中文页面，在 1280px 和 390px 浏览器视口均复现：输入 `#ff0000` 后预览变红，但 HEX 仍为 `#3B82F6`、RGB 仍为 `rgb(59, 130, 246)`。这排除了选色事件未触发和整个组件未加载的解释；`rgb`、`hsl`、`colorFormats` 原本只在组件初始化计算。

- 改为 Svelte `$derived`，让显示值、RGB 分量与复制内容跟随当前颜色。
- 按 impeccable 的 harden 指引保持现有界面，手机改为上下布局和单列格式值，不再截断颜色代码。
- 新增真实 SSR 浏览器回归：HEX 输入、原生颜色输入、预设颜色、最近颜色、复制内容以及水平溢出检查。复制 API 在测试浏览器内拦截，不使用宿主剪贴板。
- 中英文说明原来否认 RGBA 输出，与实际不符；现明确支持 RGBA，但 alpha 固定为 1，不能调整透明度。

### 2. 时区转换的默认 UTC 与“当前时间”错误（已修复并复测）

固定瞬间为 `2026-10-08T23:30:00Z`，分别使用 UTC、上海、洛杉矶浏览器时区复现：

- `Intl.supportedValuesOf('timeZone')` 不含 UTC，但组件默认选 UTC，导致源时区选择框空白。
- 初始化与“当前时间”把 `toISOString()` 的 UTC 日期和 `toTimeString()` 的浏览器本地时间拼接，再当成选定源时区解释。上海浏览器得到 `2026-10-08 07:30`，并非该时刻的 UTC 时间；选东京后点击“当前时间”也不是东京时间。

修复将 UTC 显式纳入列表；初始化只在挂载时执行，日期和时间均由同一个瞬间按选定源时区格式化，使用 00–23 小时制。清空输入不再被初始化逻辑强制覆盖。没有重写时区转换算法。

中文正文原来承诺 Temporal API、Web Worker、毫秒输入、最多五个目标时区和分享链接，均不符合现有组件。已改为真实的 Intl、单目标、分钟输入、自动更新与复制结果；英文删除不存在的“Click Convert”步骤。中英文合并后的文案已加入回归测试。

**仍有限制：** 夏令时切换时不存在/重复的当地时间没有显式消歧界面。本轮不宣称解决 DST 歧义；中文说明已提醒重要日程需用日历复核。其他语言尚未完成同等逐项内容审查。

### 3. 本地 GSC 候选清单与可索引集合不一致（已修复）

`docs/GSC_SUBMIT_URLS.txt` 原有 1,724 个唯一 URL，漏了 85 个当前保留 URL，同时包含 14 个已下线世界杯 URL。保留原有有效顺序、删除这 14 个 URL，并追加缺失的 85 个后，集合与 sitemap 的 1,795 个可索引工具 URL 一致。

这不是新增开放 85 个页面：它们本来就已保留。只调整本地候选清单，没有提交索引请求，也没有运行会重写每日批次文件的生成器。已有每日批次未经本轮同步，不能直接视为最新提交计划。

### 4. 搜索引擎检查器仍强制元描述 50–180 字符（已修复）

AI 目录真实描述为 181 字符；第三阶段停止硬截断后，旧校验因此失败。检查器现将长度作为编辑提示，仍拒绝缺失描述，并将 AI 目录渲染描述与原始文案精确比较；未提高长度上限来掩盖问题，也未修改目录文案。canonical、robots、结构化数据和正文检查保留。
