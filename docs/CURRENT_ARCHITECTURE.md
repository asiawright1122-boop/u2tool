# Current Architecture

This document describes the current production architecture of U2Tool. It supersedes older architecture notes that describe a Vercel thin-shell model.

## Runtime model

U2Tool is an Astro 6 server-rendered site deployed to Cloudflare Workers.

```text
Request
  -> Cloudflare Worker entrypoint
  -> Astro middleware
  -> Astro route
  -> BaseLayout
  -> static SEO/support content
  -> Svelte interactive island when needed
```

Key files:

- `astro.config.mjs`
- `wrangler.jsonc`
- `src/worker.ts`
- `src/middleware.ts`
- `src/layouts/BaseLayout.astro`

## Cloudflare Worker entrypoint

`src/worker.ts` wraps `@astrojs/cloudflare/entrypoints/server`.

It handles legacy build asset requests before passing all other requests to Astro.

It also normalizes `/api/ai-discovery/events` and `/api/ai-discovery/events/` at the Worker entrypoint and delegates those requests to the shared AI Discovery telemetry handler. This avoids API requests being affected by page-level trailing-slash and canonical redirect behavior.

## Dormant Cloudflare Pages project

A Cloudflare Pages project named `u2tool` still exists in the account and is bound to `u2tool.com` and `www.u2tool.com`. It is fully shadowed by the Worker route and serves no production traffic. Verified 2026-08-08:

| Property | Value |
| --- | --- |
| Bound domains | `u2tool.pages.dev`, `u2tool.com`, `www.u2tool.com` |
| Deploy trigger | Git integration, not any file in `.github/workflows/` |
| `pages_build_output_dir` | `dist` |
| Pages response | 404 at `/` and `/en/tools/` |
| Actual production server | Worker |

Two consequences. Every push builds twice, since the Git integration fires independently of `deploy-cloudflare.yml`. And the project is broken rather than merely idle: `pages_build_output_dir` is `dist`, but Astro `output: 'server'` emits `dist/client` and `dist/server`, so the directory Pages serves contains no `index.html` and no `_redirects`.

To confirm which side serves a request, check the `x-u2tool-html-cache` response header. `src/middleware.ts` sets it; Pages cannot produce it.

The bindings are deliberately left in place. Unbinding a Pages custom domain may remove the DNS record that the binding created, and a proxied record hides its CNAME chain behind the zone's anycast IPs, so `u2tool.com` and `www.u2tool.com` cannot be classified from public DNS alone. If those records are Pages-managed, unbinding takes the site offline. Read-only inspection cannot rule that out, so any cleanup must start by identifying each record's origin in the dashboard. Deleting the project carries the same unresolved risk.

## Middleware responsibilities

`src/middleware.ts` is the canonical request-normalization layer.

It handles:

- legacy route redirects
- unlocalized route redirects into `/en/...`
- trailing slash normalization
- security headers
- HTML edge caching on Cloudflare
- HEAD response conversion
- legacy build asset gone responses

HTML cache keys include `__U2TOOL_HTML_CACHE_VERSION__`, injected by `astro.config.mjs` from the current git revision plus dirty state.

## Tool runtime

Tool detail pages are served by:

- `src/pages/[locale]/tools/[slug].astro`

The page renders static, crawler-visible content first, then loads the interactive Svelte component through:

- `src/components/tools/ToolWrapper.svelte`
- `src/components/tools/ToolImportMap.ts`

`ToolImportMap.ts` is generated by:

- `scripts/generate-tool-import-map.ts`

Do not edit `ToolImportMap.ts` manually.

## Localization model

Supported locales are defined in:

- `src/lib/i18n.ts`

Supported locales:

```text
en, zh, ja, ko, es, pt, fr, de, ru, ar
```

Message loading is handled by:

- `src/lib/translations.ts`

Message assets live in:

- `src/messages/<locale>/base.json`
- `src/messages/<locale>/tools/<slug>.json`

`astro.config.mjs` copies `src/messages/` into the build output after build so Worker SSR can load runtime message assets.

## AI Discovery

AI Discovery is a deterministic matching layer, not an external LLM call.

Core files:

- `src/pages/[locale]/ai.astro`
- `src/pages/api/ai-discovery/search.ts`
- `src/pages/api/ai-discovery/events.ts`
- `src/lib/ai-discovery/search-service.ts`
- `src/lib/ai-discovery/index-builder.ts`
- `src/lib/ai-discovery/matcher.ts`

Feature flag:

```text
PUBLIC_AI_DISCOVERY_ENABLED=true
```

The matcher uses localized tool metadata, comparison guide candidates, aliases, and intent dictionaries to return `direct`, `suggest`, or `fallback` decisions.
