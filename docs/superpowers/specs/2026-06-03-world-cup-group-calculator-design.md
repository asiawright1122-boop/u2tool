# 设计规约 - 2026美加墨世界杯小组晋级与对决推演器 🏆 🧮

---

## 1. 背景与目标 (Background & Goals)

### 1.1 背景
2026 年 FIFA 美加墨世界杯首次由 32 支球队扩军至 **48 支球队**，赛制发生了重大改变：
1. 小组赛阶段共 12 个小组（A - L 组），每组 4 支球队，共 72 场小组赛。
2. 晋级 32 强的规则：每个小组的前两名（共 24 支球队）直接晋级，加上成绩最好的 8 个小组第三名（共 8 支球队）。
3. 32 强（Round of 32）中，这 8 个小组第三名该去对阵哪几个特定的第一名，其匹配关系是由 FIFA 官方规章（Annex C 对决分配表）根据哪 8 个小组的第三名晋级这一组合（共 $C_{12}^8 = 495$ 种可能性）决定的。这给球迷在进行模拟推演时带来了极大的逻辑换算痛苦。

### 1.2 目标
开发一款**世界杯小组晋级与对决推演器** (slug: `world-cup-group-calculator`)，支持：
1. **72 场小组赛比分推演**：用户可点击或输入预测比分，系统实时计算并更新 A - L 组积分榜。
2. **同分智能微调**：内置积分榜规则，遇到完全同分（积分、净胜球、进球等决胜指标均相同）的情况时，允许在积分榜上“一键互换排名”进行人工决策。
3. **最好第三名大排名精算**：提取 12 个小组的第三名，根据成绩（积分、净胜球、进球）进行全量横向大排名，确定前 8 名出线队伍。
4. **495 种淘汰赛对战一键映射**：利用抓取的 Wikipedia 官方 495 种组合对照字典，在比分变动时自动精算并更新 32 强（Round of 32）到决赛的对决树。
5. **Obsidian 曜石暗金高奢风格**：采用奢华黑金渐变，Scoped Style 隔离，适配 10 国语言，确保极高体验与健壮的无污染样式。

## 2. 算路引擎与数据设计 (System & Data Design)

### 2.1 基础赛程数据源
通过静态读取 `src/lib/data/world-cup-schedule.json` 过滤出 `stage === 'group'` 作为小组赛，其余为淘汰赛骨架。此外，在静态数据中注入各队最新的 **FIFA 世界排名 (FIFA World Ranking)** 值，用于在大排名完全同分且无相互战绩可用时进行终极自动决胜。

### 2.2 离线爬虫与映射字典 (`world-cup-3rd-combinations.json`)
由于这 495 种组合的对决极其繁琐且带有官方战术回避逻辑（非单纯数学公式可拟合），我们将：
1. 编写 Node 爬虫脚本 `scripts/scrape-wc-combinations.ts`，自动从维基百科 `https://en.wikipedia.org/wiki/2026_FIFA_World_Cup_knockout_stage` 提取“Combinations of matches in the round of 32”的大型表格。
2. 将解析结果格式化为包含 495 行键值对的 JSON 字典，保存至 `src/lib/data/world-cup-3rd-combinations.json`。
3. **数据项格式**：
   ```json
   {
     "ACDFGHIL": {
       "M75": "3D",
       "M76": "3A",
       "M81": "3L",
       "M82": "3I",
       "M87_H": "3E",
       "M87_A": "3G",
       "M88_H": "3C",
       "M88_A": "3K"
     }
   }
   ```
   * *键 (Key)*：8 个晋级的小组第三名所属的组别字母（按字母顺序升序排列，例如 A、C、D、F、G、H、I、L 组晋级，则键为 `"ACDFGHIL"`）。
   * *值 (Value)*：映射出 32 强各对应场次（M75, M76, M81, M82, M87_H, M87_A, M88_H, M88_A）的具体小组第三（例如 `"3D"` 表示来自 D 组的第三名）。

### 2.3 小组同分决胜 (Tie-breaker) 与大排名规则
1. **小组内同分决胜顺序** (依据 FIFA 官方规章)：
   1. 比较同分球队之间的**相互比赛积分 (Head-to-head Points)**。
   2. 比较同分球队之间的**相互比赛净胜球 (Head-to-head Goal Difference)**。
   3. 比较同分球队之间的**相互比赛进球数 (Head-to-head Goals Scored)**。
   4. 比较全部小组赛的**总净胜球 (Overall Goal Difference)**。
   5. 比较全部小组赛的**总进球数 (Overall Goals Scored)**。
   6. 比较全部小组赛的**公平竞赛积分**（由于推演器不录入红黄牌，此项与下一项合并提供手动干预）。
   7. 若上述均相同，在积分榜相应球队行旁显示“⇅ 一键交换排名”供用户手动裁决。
2. **大排名 (小组第三横向对比) 决胜顺序**：
   1. 总积分。
   2. 总净胜球。
   3. 总进球数。
   4. **FIFA 官方世界排名 (FIFA World Ranking)**（排名高者居前）。
   5. 若世界排名及前三项均完全相同，在大排名榜单中显示“⇅ 一键交换排名”供用户人工微调。
3. **手动干预持久化**：用户干预状态以一个局部字典（如 `customTiesOverride: Record<string, string[]>`，Key 为小组名或 `"3rd_ranking"`，Value 为球队 ID 顺序数组）形式保存在内存中，并同步至 LocalStorage。当比分重新计算时，若同分条件依然成立，优先应用该顺序。

### 2.4 数据流动向
```
[用户修改/录入比分] 
       ↓
[重算 12 个小组积分榜 (按 H2H 及 Tie-breaker 规约)] ➔ (同分时应用 customTiesOverride)
       ↓
[提取各组 1st, 2nd 直接填入 32 强对应 Slot]
       ↓
[提取各组 3rd 汇总，排定“大排名”，选出前 8 个最好的小组第三名]
       ↓
[将 8 个小组第三字母按升序拼成 Key (如 ACDFGHIL)]
       ↓
[查阅 world-cup-3rd-combinations.json] ➔ 获取这 8 个第三名对阵的 32 强比赛 ID
       ↓
[更新 R32 对战队伍] ➔ 用户可点击淘汰赛继续模拟晋级 ➔ 产生最终冠亚军
```

### 2.5 淘汰赛级联失效重置 (Cascade Invalidation) 逻辑
当小组赛比分变更导致 32 强（R32）的参赛队伍发生改变时，必须清理对决树中已失效的后续节点预测状态，防止逻辑崩溃或幽灵队伍残留：
1. **变化检测**：对于淘汰赛树的每个节点（R32, R16, QF, SF, Final），其左/右输入队伍（`homeTeam`, `awayTeam`）均为派生状态 `$derived`。
2. **重置触发器**：使用 Svelte 5 的 `$effect` 监听每场淘汰赛的输入球队 ID。
3. **重置规则**：
   * 若某场比赛当前用户预测的胜者（`predictedWinner`）既不等于当前的 `homeTeam`，也不等于当前的 `awayTeam`（即预测晋级的队伍已被淘汰出此对战），则**将该比赛的预测胜者重置为 `null`**。
   * 由于上级节点的 `predictedWinner` 置空，会以骨牌效应级联导致下级比赛的输入（`homeTeam` / `awayTeam`）变为 `null`，从而触发下级节点的重置，实现自底向上的级联失效清理。

### 2.6 运行时兼容性与 i18n 多语言架构
1. **LocalStorage 与 Astro SSR 冲突防护**：
   为了防止 Node.js 服务端渲染期间抛出 `window is not defined` 或 `localStorage is not defined` 的致命错误，推演器组件在 Astro 页面中加载时必须携带 `client:only="svelte"` 属性。这将确保该组件完全在客户端单兵挂载，且避免了 hydration 期间的状态不一致问题。
2. **i18n 多语言设计**：
   * 多语言文本定义在 `src/lib/locales/` 或通过 Svelte 属性 `translations` 传入。组件内部通过 `$derived` 响应式状态管理当前语言对应的所有提示文案、国家/球队本地化名称等。
   * 支持 10 国语言一键无缝切换，所有积分榜计算出的警告、同分微调提示均支持多语言即时刷新。

## 3. UI 交互与组件设计 (UI & Components)

### 3.1 界面布局 (Layout)
采用**双栏全局大沙盘**设计：
* **左栏 (72场小组赛预测 & 积分榜)**：
  * 支持 12 个小组的垂直卡片流，支持单独折叠/展开小组。
  * 每场比赛包含两队比分输入框（支持键盘输入与微调上下箭头）。
  * 积分榜紧凑置于各组下方，实时高亮晋级线（1st, 2nd 绿线，3rd 黄线/虚线，4th 灰线）。
* **右栏 (第三名大排名 & 淘汰赛对战树)**：
  * **第三名横向排名榜**：动态更新，显示 12 个第三名中前 8 名（金色激活）和后 4 名（灰色淘汰）的实时积分数据。
  * **淘汰赛战力树 (Knockout Tree)**：展示 32强 ➔ 16强 ➔ 8强 ➔ 半决赛 ➔ 决赛的树形网格。用户可以直接在淘汰赛卡片上“点击胜者”实现一键晋级模拟。

### 3.2 Obsidian 曜石暗金高奢风格与样式污染防护
1. **全局样式隔离**：
   为推演器外层包裹一个专用的容器 `.obsidian-calculator-theme`。在容器中强行重置所有基础 HTML 元素（如 `div`, `input`, `select`, `table` 等）的 CSS 变量，确保即使在浅色模式的宿主页面中，推演器内部也始终保持高奢曜石暗金的暗色风格。
2. **色彩系统**：
   * 背景色：`#0a0a0a`（曜石极夜黑），配合 `#121212` 的卡片背景和磨砂玻璃模糊（`backdrop-blur-md`）。
   * 主色调与渐变：`#f59e0b`（曜石暗金），高光处使用 `#fbbf24` 及金沙微粒呼吸灯效果。
3. **隔离设计**：所有 CSS 使用 Svelte 自带的 CSS 模块进行样式隔离，对第三方弹层使用 `:global` 限制在 `.obsidian-calculator-theme` 容器类名之下。

## 4. 验证与测试计划 (Verification Plan)

### 4.1 自动化测试
1. **爬虫抓取提取测试**：在 `scripts/scrape-wc-combinations.ts` 运行后，编写验证程序检查是否生成了恰好 495 个不同的 Key，且每个 Key 对应的 mapping 格式完全正确。
2. **大排名计算引擎测试**：提供一组测试数据模拟小组赛比分，断言生成的小组积分和大排名结果是否完全符合 FIFA 标准。
3. **同分微调功能测试**：在同分情况下点击“交换 ⇅”，断言局部排序是否发生换位，且不被打乱。

### 4.2 手动测试
1. **比分推演闭环测试**：随意输入比分，观察小组积分榜的变更是否流畅，对阵图的自动匹配是否无卡顿、无错乱。
2. **极端比分测试**：例如所有 72 场比赛全部打平为 0-0，观察 12 个第三名的排名状态以及 32 强的匹配是否正常显示。
