# Markdown 문법 가이드: 개발자를 위한 완전한 참조

Markdown은 일반 텍스트를 사용하여 서식이 있는 콘텐츠를 작성할 수 있는 경량 마크업 언어입니다. 이 포괄적인 가이드는 기본부터 고급 기능까지 모든 Markdown 문법을 다룹니다.

## Markdown이란?

Markdown은 2004년 John Gruber가 만들었습니다. 일반 텍스트 형식으로 읽기 쉬우면서도 HTML로 변환 가능한 콘텐츠를 작성하는 방법으로 설계되었습니다. 현재 문서, README 파일, 블로그 게시물 등에 널리 사용됩니다.

## 기본 문법

### 제목

해시 기호(#)를 사용하여 제목을 만듭니다:

```markdown
# 제목 1
## 제목 2
### 제목 3
#### 제목 4
##### 제목 5
###### 제목 6
```

### 텍스트 서식

- **굵게**: `**굵은 텍스트**` 또는 `__굵은 텍스트__`
- *기울임*: `*기울임 텍스트*` 또는 `_기울임 텍스트_`
- ***굵은 기울임***: `***굵은 기울임 텍스트***`
- ~~취소선~~: `~~취소선~~`
- `코드`: `` `인라인 코드` ``

### 목록

**순서 없는 목록:**
```markdown
- 항목 1
- 항목 2
  - 중첩된 항목
  - 또 다른 중첩된 항목
- 항목 3
```

**순서 있는 목록:**
```markdown
1. 첫 번째 항목
2. 두 번째 항목
3. 세 번째 항목
```

### 링크와 이미지

**링크:**
```markdown
[링크 텍스트](https://example.com)
[제목이 있는 링크](https://example.com "제목")
```

**이미지:**
```markdown
![대체 텍스트](image-url.jpg)
![대체 텍스트](image-url.jpg "이미지 제목")
```

## 고급 문법

### 코드 블록

구문 강조가 있는 코드 블록에는 삼중 백틱을 사용합니다:

```javascript
function greet(name) {
  return `안녕하세요, ${name}님!`;
}
```

### 테이블

```markdown
| 헤더 1 | 헤더 2 | 헤더 3 |
|--------|--------|--------|
| 셀 1   | 셀 2   | 셀 3   |
| 셀 4   | 셀 5   | 셀 6   |
```

### 인용문

```markdown
> 이것은 인용문입니다.
> 여러 줄에 걸쳐 작성할 수 있습니다.
>
> > 중첩된 인용문도 가능합니다.
```

### 작업 목록

```markdown
- [x] 완료된 작업
- [ ] 미완료 작업
- [ ] 또 다른 작업
```

### 수평선

세 개 이상의 하이픈, 별표 또는 밑줄을 사용합니다:

```markdown
---
***
___
```

## 확장 Markdown 기능

### 각주

```markdown
이것은 각주가 있는 문장입니다.[^1]

[^1]: 이것은 각주 내용입니다.
```

### 정의 목록

```markdown
용어
: 용어의 정의
```

### 약어

```markdown
HTML 사양은 W3C에서 관리합니다.

*[HTML]: Hyper Text Markup Language
*[W3C]: World Wide Web Consortium
```

## 모범 사례

1. **일관된 서식 사용** - 문서 전체에서 하나의 스타일 유지
2. **빈 줄 추가** - 가독성을 위해 다른 요소를 빈 줄로 구분
3. **참조 스타일 링크 사용** - 링크가 많은 문서에서는 참조 스타일로 소스를 깔끔하게 유지
4. **작업 미리보기** - 게시 전에 항상 Markdown 미리보기
5. **단순하게 유지** - 복잡하게 만들지 않기; Markdown은 가독성을 위한 것

## 일반적인 사용 사례

- **README 파일** - GitHub의 프로젝트 문서
- **문서** - 기술 문서 및 위키
- **블로그 게시물** - 콘텐츠 관리 시스템
- **메모** - 개인 메모 애플리케이션
- **댓글** - 포럼 및 토론 플랫폼

## 결론

Markdown은 개발자와 콘텐츠 제작자에게 필수적인 기술입니다. 단순함과 가독성으로 인해 기술 문서의 선호되는 선택이 되었습니다. 이러한 문법 요소를 연습하면 곧 Markdown을 유창하게 작성할 수 있을 것입니다.
