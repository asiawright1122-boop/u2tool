## 일반적인 비밀번호 공격

### 1. 무차별 대입 공격

모든 가능한 조합 시도:

```
a, b, c, ... aa, ab, ac, ... aaa, aab, ...
```

**방어**: 혼합 문자를 포함한 긴 비밀번호

### 2. 사전 공격

일반적인 단어와 비밀번호 사용:

```
password, 123456, qwerty, admin, letmein...
```

**방어**: 사전 단어 피하기

### 3. 크리덴셜 스터핑

다른 침해에서 유출된 자격 증명 사용:

```
email: user@example.com
password: 사이트A에서 유출된 비밀번호
```

**방어**: 각 계정에 고유한 비밀번호

### 4. 피싱

사용자를 속여 비밀번호를 공개하게 함:

```
가짜 로그인 페이지 -> 자격 증명 캡처
```

**방어**: URL 확인, 2FA 사용

## 사용자를 위한 모범 사례

### 해야 할 것 ✅

1. 모든 계정에 **고유한 비밀번호** 사용
2. **비밀번호 관리자** 사용(1Password, Bitwarden 등)
3. 가능한 곳에서 **2FA/MFA** 활성화
4. 최소 **12자 이상** 사용
5. **모든 문자 유형** 포함(대문자, 소문자, 숫자, 기호)
6. 침해 후 **비밀번호 변경**
7. 가능한 경우 **패스키** 사용(비밀번호 없음)

### 하지 말아야 할 것 ❌

1. 계정 간 비밀번호 **재사용 금지**
2. **개인 정보** 사용 금지(생일, 이름, 반려동물)
3. **일반적인 패턴** 사용 금지(Password1!, Qwerty123)
4. 이메일이나 문자로 비밀번호 **공유 금지**
5. 포스트잇에 비밀번호 **적지 않기**
6. 실제 답변으로 **보안 질문** 사용 금지
7. 침해 알림 **무시 금지**

## FAQ

### 비밀번호는 얼마나 자주 변경해야 하나요?

현재 지침(NIST 2024): 일정에 따라 비밀번호를 변경하지 마세요. 다음 경우에만 변경:
- 침해 의심
- 서비스가 침해 보고
- 비밀번호를 공유함
- 약한 비밀번호 사용

잦은 강제 변경은 더 약한 비밀번호로 이어집니다.

### 긴 비밀번호가 항상 좋은가요?

일반적으로 예, 하지만 품질도 중요합니다. "aaaaaaaaaaaa"(12자)는 "Tr0ub4dor&3"(11자)보다 약합니다. 길이와 복잡성 모두를 목표로 하세요.
