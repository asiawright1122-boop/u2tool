# 密码安全最佳实践：2025 完整指南

密码安全仍然是网络安全最关键的方面之一。本指南涵盖如何创建强密码、常见攻击方式，以及用户和开发者的最佳实践。

## 为什么密码安全很重要

根据最新的网络安全报告：

- **81%** 的数据泄露涉及弱密码或被盗密码
- **65%** 的人在多个账户中重复使用密码
- **2300 万** 个账户仍在使用 "123456" 作为密码
- 数据泄露的平均成本：**445 万美元**

## 什么是强密码？

### 密码强度因素

| 因素 | 弱 | 强 |
|------|-----|-----|
| 长度 | 6-8 字符 | 12+ 字符 |
| 字符类型 | 仅字母 | 混合（大小写、数字、符号） |
| 可预测性 | 字典词汇 | 随机组合 |
| 唯一性 | 重复使用 | 每个账户唯一 |

### 密码熵

密码强度以熵的比特数衡量：

```
熵 = log2(可能字符数 ^ 长度)

示例：
- 8 个小写字母：log2(26^8) = 37.6 比特（弱）
- 12 个混合字符：log2(95^12) = 78.8 比特（强）
```

### 破解时间（2025 年估计）

| 密码类型 | 示例 | 破解时间 |
|----------|------|----------|
| 6 个小写字母 | `abcdef` | 瞬间 |
| 8 个小写字母 | `password` | 5 秒 |
| 8 个混合大小写 | `PassWord` | 22 分钟 |
| 8 个混合 + 数字 | `Pass1234` | 1 小时 |
| 12 个混合 + 符号 | `P@ss1234!abc` | 34,000 年 |
| 16 个随机字符 | `kX9#mP2$vL5@nQ8&` | 数世纪 |

## 常见密码攻击

### 1. 暴力破解攻击

尝试每种可能的组合：

```
a, b, c, ... aa, ab, ac, ... aaa, aab, ...
```

**防御**：使用混合字符的长密码

### 2. 字典攻击

使用常见词汇和密码：

```
password, 123456, qwerty, admin, letmein...
```

**防御**：避免字典词汇

### 3. 彩虹表攻击

使用预计算的哈希表：

```
哈希 -> 密码查找
5f4dcc3b5aa765d61d8327deb882cf99 -> password
```

**防御**：使用加盐哈希（针对开发者）

### 4. 凭据填充

使用其他泄露的凭据：

```
邮箱：user@example.com
密码：从网站 A 泄露的密码
```

**防御**：每个账户使用唯一密码

### 5. 钓鱼攻击

诱骗用户泄露密码：

```
假登录页面 -> 捕获凭据
```

**防御**：验证 URL，使用双因素认证

### 6. 社会工程

心理操纵用户：

```
"我是 IT 支持，我们需要您的密码来修复问题"
```

**防御**：永不分享密码，验证请求

## 用户密码最佳实践

### 应该做 ✅

1. **每个账户使用唯一密码**
2. **使用密码管理器**（1Password、Bitwarden 等）
3. **尽可能启用双因素认证**
4. **最少使用 12 个以上字符**
5. **包含所有字符类型**（大小写、数字、符号）
6. **泄露后更改密码**
7. **可用时使用通行密钥**（无密码）

### 不应该做 ❌

1. **不要跨账户重复使用密码**
2. **不要使用个人信息**（生日、姓名、宠物）
3. **不要使用常见模式**（Password1!、Qwerty123）
4. **不要通过邮件或短信分享密码**
5. **不要把密码写在便签上**
6. **不要使用真实答案的安全问题**
7. **不要忽视泄露通知**

## 开发者密码安全

### 密码哈希

永远不要存储明文密码：

```javascript
// 不好 - 明文
db.save({ password: "user_password" });

// 好 - 使用 bcrypt 哈希
const hash = await bcrypt.hash(password, 12);
db.save({ password: hash });
```

### 推荐哈希算法

| 算法 | 推荐 | 说明 |
|------|------|------|
| bcrypt | ✅ 推荐 | 自适应，广泛支持 |
| Argon2 | ✅ 最佳 | PHC 获胜者，内存硬 |
| scrypt | ✅ 好 | 内存硬 |
| PBKDF2 | ⚠️ 可接受 | 使用高迭代次数 |
| SHA-256 | ❌ 不要使用 | 太快，无盐 |
| MD5 | ❌ 永不 | 已破解，不安全 |

### 密码验证规则

```javascript
const passwordRules = {
  minLength: 12,
  maxLength: 128,
  requireUppercase: true,
  requireLowercase: true,
  requireNumbers: true,
  requireSymbols: true,
  preventCommon: true,  // 检查常见密码
  preventUserInfo: true // 密码中不能有用户名、邮箱
};
```

### 速率限制

防止暴力破解攻击：

```javascript
// 限制登录尝试
const limiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 分钟
  max: 5, // 5 次尝试
  message: "登录尝试次数过多"
});
```

### 账户锁定

```javascript
if (failedAttempts >= 5) {
  lockAccount(userId, duration: '30m');
  notifyUser(userId, '由于多次失败尝试，账户已锁定');

```

## 常见问题

### 我应该多久更改一次密码？

当前指南（NIST 2024）：不要按计划更改密码。只在以下情况更改：
- 怀疑泄露
- 服务报告泄露
- 分享过密码
- 使用了弱密码

频繁强制更改会导致更弱的密码。

### 更长的密码总是更好吗？

通常是的，但质量也很重要。"aaaaaaaaaaaa"（12 字符）比 "Tr0ub4dor&3"（11 字符）弱。目标是长度和复杂性兼顾。

### 密码短语比随机密码更安全吗？

4 个词的密码短语如 "correct-horse-battery-staple" 大约有 44 比特熵。12 字符的随机密码大约有 79 比特。随机密码更强，但密码短语更容易记忆。

### 我应该使用特殊字符吗？

是的，但不要只在末尾加 "!"。在整个密码中分布特殊字符。"P@ss!w0rd#2025" 比 "Password2025!" 更好。

### 如果我记不住复杂密码怎么办？

使用密码管理器。你只需要记住一个强主密码。管理器处理其他一切。

### 生物识别比密码更安全吗？

生物识别很方便但有局限性：
- 如果泄露无法更改
- 可以被欺骗（指纹、面部照片）
- 最好作为第二因素，而不是替代品
