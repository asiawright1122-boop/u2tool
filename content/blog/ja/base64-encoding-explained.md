# Base64エンコーディング解説：オンラインツール付き完全ガイド

Base64は、64個の印刷可能な文字を使用してバイナリデータを表現するエンコーディング方式です。Web開発、データ転送、メール添付ファイルなどで広く使用されています。この記事では、Base64の仕組みと実用的なオンラインツールを紹介します。

## Base64エンコーディングとは？

Base64エンコーディングは、以下の64文字を使用してデータを表現します：
- 大文字：A-Z（26）
- 小文字：a-z（26）
- 数字：0-9（10）
- 特殊文字：+ と /（2）

さらに、= がパディング文字として使用されます。

## Base64エンコーディングの仕組み

Base64の核心原理は、3バイト（24ビット）のデータを4つのBase64文字（各6ビット）に変換することです。

### エンコーディング手順

1. 入力データをバイナリに変換
2. 6ビットグループに分割
3. 各グループを対応するBase64文字に変換
4. 最終グループが不完全な場合は = でパディング

### 例

"Hi"をBase64にエンコード：

```
H = 01001000
i = 01101001

結合: 010010 000110 1001xx

パディング後: 010010 000110 100100

対応: S      G      k      =

結果: SGk=
```

## 一般的な使用例

### 1. インライン画像

HTML/CSSに画像を直接埋め込む：

```html
<img src="data:image/png;base64,iVBORw0KGgo..." />
```

### 2. APIデータ転送

JSONでバイナリデータを転送：

```json
{
  "file": "SGVsbG8gV29ybGQh",
  "filename": "hello.txt"
}
```

### 3. メール添付ファイル

MIMEプロトコルはメール添付ファイルにBase64を使用します。

### 4. JWTトークン

JSON Web TokensはBase64URLエンコーディングを使用します。

## Base64の長所と短所

### 長所
- テキストプロトコルでバイナリデータを転送
- エンコードされたデータは印刷可能な文字のみを含む
- すべてのプログラミング言語で広くサポート

### 短所
- エンコードされたデータは約33%大きくなる
- 暗号化ではない、セキュリティには使用しない

## よくある質問（FAQ）

### Base64は暗号化ですか？

いいえ、Base64はエンコーディングであり、暗号化ではありません。セキュリティは提供されません - 誰でもBase64データをデコードできます。機密情報の保護にBase64を使用しないでください。セキュリティにはAESなどの適切な暗号化アルゴリズムを使用してください。

### なぜBase64はファイルサイズを増加させるのですか？

Base64は3バイトを4文字に変換するため、約33%のサイズ増加が発生します。これは、256の可能なバイト値を表すために64の印刷可能な文字のみを使用するためです。

### Base64URLとは何ですか？

Base64URLはBase64のURL安全バリアントです。`+`を`-`に、`/`を`_`に置き換え、パディング`=`を省略することが多いです。JWTトークンやURLパラメータで一般的に使用されます。

### いつBase64を使用すべきですか？

以下の場合にBase64を使用します：
- HTML/CSSに画像を埋め込む（data URI）
- JSON APIでバイナリデータを転送する
- テキストのみのシステムでバイナリデータを保存する
- メール添付ファイルをエンコードする（MIME）

### Base64はどんなファイルタイプでもエンコードできますか？

はい、Base64は画像、PDF、実行ファイル、その他あらゆるファイルタイプを含む任意のバイナリデータをエンコードできます。エンコード結果は常にプレーンテキストです。
