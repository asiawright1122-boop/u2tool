# Plan 23-02: Split GSC Performance Loss by Page and Query

## Goal

Determine whether the remaining traffic loss is primarily exposure, CTR, click capture, or average-position movement.

## Required Input

Place GSC Performance exports in:

```text
exports/gsc/
```

Required files:

- `pages-current.csv` or `.xlsx`
- `pages-previous.csv` or `.xlsx`
- `queries-current.csv` or `.xlsx`
- `queries-previous.csv` or `.xlsx`

Use a 28-day current window and the previous 28-day comparison window.

## Steps

1. Run the existing recovery report:

```bash
npm run report:gsc-recovery -- \
  --input-dir exports/gsc \
  --output docs/GSC_PERFORMANCE_RECOVERY_REPORT_2026-05-06.md
```

2. Segment pages by type:
   - homepage
   - tools index
   - tool detail
   - category page
   - compare page
   - AI/llms/discovery surfaces

3. Segment queries by intent:
   - exact tool intent
   - category intent
   - comparison intent
   - brand intent
   - informational/support intent

4. Decide work type:
   - Impressions down, position down: content trust, canonical trust, topical usefulness, or competitive loss.
   - Impressions stable, CTR down: title/meta/snippet mismatch, SERP feature loss, or weaker promise clarity.
   - CTR stable, clicks down: exposure loss dominates.
   - Position stable, impressions down: demand/query allocation or de-indexed query cluster.

## Verification

Any patch from this plan must pass:

```bash
npm run qa:seo-governance
npm run check
npm run build
npm run validate:rendered-seo
npm run validate:search-engine-compliance
npm run validate:growth-surfaces
```

## Success Criteria

- The performance report separates exposure, CTR, clicks, and position.
- Priority pages and queries are ranked by recoverable opportunity, not emotion or guesswork.
- Only proven page/query groups receive title, meta, content, or internal-link changes.
