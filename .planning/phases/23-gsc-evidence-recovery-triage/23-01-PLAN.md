# Plan 23-01: Classify GSC Coverage URL Drilldowns

## Goal

Classify concrete GSC Coverage URL samples before making any further SEO, routing, canonical, noindex, or redirect changes.

## Required Input

Place exported GSC Coverage drilldown CSVs in:

```text
exports/gsc/coverage-drilldowns/
```

Priority exports:

- `已抓取 - 尚未编入索引`
- `重复网页，Google 选择的规范网页与用户指定的不同`
- `被“noindex”标记排除了`
- `由于遇到其他 4xx 问题而被屏蔽了`
- `未找到 (404)`

## Steps

1. Confirm the required exports are present:

```bash
npm run check:gsc-recovery-inputs
```

2. Run the existing classifier:

```bash
npm run report:gsc-drilldown -- \
  --input-dir exports/gsc/coverage-drilldowns \
  --output docs/GSC_DRILLDOWN_URL_REPORT_2026-05-04.md
```

3. Review top buckets by:
   - issue type
   - host bucket
   - locale
   - page type
   - canonical/redirect signal

4. For each P0/P1 bucket, live-check representative URLs:
   - HTTP status
   - final redirect target
   - robots meta
   - canonical
   - sitemap presence
   - internal-link source
   - rendered body usefulness

5. Decide action by evidence:
   - Fix bad canonical/noindex only when a live indexable page is affected.
   - Remove stale internal links when internal discovery points to redirects or 404s.
   - Redirect only high-value legacy URLs with clear replacements.
   - Leave expected alternate canonical URLs alone when signals are coherent.

## Verification

Run the relevant checks after any patch:

```bash
npm run validate:rendered-seo
npm run validate:search-engine-compliance
npm run validate:technical-seo
npm run validate:sitemap-url-health
npm run validate:internal-link-canonicals
```

## Success Criteria

- The drilldown report exists and identifies systematic patterns.
- Every recommended code/content change links back to a GSC issue bucket.
- No broad redirect or title/meta rewrite is made without URL-level evidence.
