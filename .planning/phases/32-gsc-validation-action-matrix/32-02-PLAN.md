# 32-02 Plan

## Goal

Document the current GSC validation and request-indexing playbook so the user knows exactly what to do after failed broad validation attempts.

## Must Be True

1. The playbook tells the user not to retry broad validation for mixed/expected exclusion rows.
2. The playbook lists what to fix or inspect before validating `4xx`, `404`, `noindex`, robots, or server-error groups.
3. The playbook lists how to handle high-value pages: enhance first, inspect live URL, then request indexing individually.

## Initial Tasks

- Read `docs/GSC_VALIDATION_ACTION_MATRIX_2026-05-11.md`, `docs/GSC_DRILLDOWN_URL_REPORT_2026-05-11.md`, and `docs/GSC_PERFORMANCE_RECOVERY_REPORT_2026-05-11.md`.
- Write `docs/GSC_VALIDATION_PLAYBOOK_2026-05-11.md` with:
  - a short answer to "why did previous validation fail?";
  - issue-row guidance for `Page with redirect`, `Alternate with proper canonical`, `Crawled - currently not indexed`, `Excluded by noindex`, `Blocked due to 4xx`, and `Not found (404)`;
  - a "do today" list that does not require new exports;
  - a "validate only after" checklist for fixed groups;
  - individual request-indexing instructions for later Phase 34 candidates.
- Write `32-01-SUMMARY.md` and `32-02-SUMMARY.md` after implementation.
- Update `.planning/REQUIREMENTS.md`, `.planning/ROADMAP.md`, `.planning/STATE.md`, and `.planning/TRACEABILITY.md` for Phase 32 progress.
