# 32-01 Plan

## Goal

Generate a deterministic GSC validation action matrix from the existing Coverage drilldown and Performance exports.

## Must Be True

1. Existing GSC exports are validated before report generation.
2. The generated matrix labels URL groups as `do-not-validate`, `fix-before-validate`, `request-indexing-after-enhancement`, or `monitor`.
3. The matrix includes issue counts, page/signal breakdowns, examples, and the reason each group should or should not be sent through GSC validation.

## Initial Tasks

- Read `scripts/seo/check-gsc-recovery-inputs.ts`, `scripts/seo/gsc-drilldown-url-report.ts`, and `scripts/seo/gsc-recovery-report.ts`.
- Add a report generator, likely `scripts/seo/gsc-validation-action-matrix.ts`, that:
  - loads `exports/gsc/coverage-drilldowns/*.csv`;
  - loads `exports/gsc/pages-current.xlsx` and `exports/gsc/pages-previous.xlsx`;
  - reuses or mirrors the existing URL classification logic from `gsc-drilldown-url-report.ts`;
  - assigns each grouped row one of the four Phase 32 action labels;
  - emits `docs/GSC_VALIDATION_ACTION_MATRIX_2026-05-11.md`.
- Add a package script such as `report:gsc-validation-matrix`.
- Keep the report deterministic: stable ordering, stable examples, no live network calls.

## Verification

```bash
npm run check:gsc-recovery-inputs
npm run report:gsc-validation-matrix -- --input-dir exports/gsc --output docs/GSC_VALIDATION_ACTION_MATRIX_2026-05-11.md
git diff --check
```

## Success Criteria

- `docs/GSC_VALIDATION_ACTION_MATRIX_2026-05-11.md` exists and explains the current GSC validation posture.
- The matrix makes clear that stale assets, canonical alternates, redirects, query variants, and canonical-shape variants should not be broadly revalidated.
- Potential true blockers and high-value request-indexing candidates are separated for Phase 33 and Phase 34.
