# 24-02 Plan

## Goal

Wire representative office tools to the repaired scheduling helpers and prove behavior with direct smoke evidence.

## Must Be True

1. `TimezoneMeetingScheduler.svelte` computes local times through a source-aware timezone conversion helper.
2. `CalendarAvailabilityFinder.svelte` uses shared scheduling behavior or remains behaviorally equivalent with a documented compatibility path.
3. Tests cover normal, overlapping, invalid, boundary, and cross-timezone cases through the public `tool-stubs.ts` exports.

## Initial Tasks

- Update `TimezoneMeetingScheduler.svelte` only if needed to consume normalized helper outputs cleanly.
- Replace duplicated `CalendarAvailabilityFinder.svelte` time/availability helpers with imports from `tool-stubs.ts` when the shared API matches the component needs.
- Extend `src/lib/tool-stubs-runtime.test.ts` with scheduling cases:
  - valid and invalid `parseTimeToMinutes`
  - `formatMinutesToTime` and `formatHour` boundary behavior
  - overlapping busy slots producing the expected free windows
  - conflict parsing from structured and text input
  - source-aware timezone conversion for a stable representative date/zone pair
- If `qa:runtime-integrity` remains absent from `package.json`, record that Phase 26 should restore or replace that governance entrypoint.

## Verification

Run the behavior and framework checks:

```bash
npx vitest run src/lib/tool-stubs-runtime.test.ts
npm run check
npm run build
```

If the implementation touches release-gate scripts or package scripts, also run:

```bash
git diff --check
```

## Success Criteria

- Representative office tools no longer depend on empty shared helper exports for time/scheduling behavior.
- Runtime smoke tests fail if the repaired helpers regress to empty arrays, empty objects, empty strings, or source-ignoring timezone conversion.
- Phase 24 can close with clear evidence for `RUNTIME-04`.
