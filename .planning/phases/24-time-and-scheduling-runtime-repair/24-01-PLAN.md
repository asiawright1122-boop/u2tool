# 24-01 Plan

## Goal

Map the time/scheduling helper surface and extract real shared runtime behavior behind `tool-stubs.ts`.

## Must Be True

1. The selected helper exports have stable public contracts before implementation starts.
2. The shared implementation lives in `src/lib/runtime-integrity/` and keeps `src/lib/tool-stubs.ts` as the compatibility surface.
3. Existing component-local behavior from representative office tools is preserved or improved without broad UI churn.

## Initial Tasks

- Reconfirm current consumers of `TIMEZONES`, `convertTime`, `formatHour`, `findAvailableSlots`, `parseConflicts`, `parseTimeToMinutes`, and `formatMinutesToTime`.
- Add `src/lib/runtime-integrity/scheduling.ts` with typed helpers for:
  - parsing time input into minutes
  - formatting minutes and hours
  - merging busy slots
  - finding available slots inside a work window
  - parsing conflict/busy-window input
  - converting source timezone wall-clock time to target timezone wall-clock time
- Delegate the selected exports in `src/lib/tool-stubs.ts` to the shared scheduling module.
- Keep `TIMEZONES` shape stable unless a compatibility-safe extension is needed.

## Verification

Run targeted smoke coverage after implementation:

```bash
npx vitest run src/lib/tool-stubs-runtime.test.ts
```

Then run the standard source checks before committing code:

```bash
npm run check
```

## Success Criteria

- `findAvailableSlots`, `parseTimeToMinutes`, `formatMinutesToTime`, `formatHour`, `parseConflicts`, and `convertTime` no longer use placeholder behavior.
- The shared scheduling module is typed, deterministic, and non-throwing for invalid or partial input.
- Public exports from `tool-stubs.ts` remain compatible with existing consumers.
