## Milestone Goal

This is another **bounded metadata cleanup** milestone. It does not redesign validators, change thresholds, or mass-edit multilingual copy. The expected outcome is a measured 10-warning reduction while preserving `0` hard errors and synchronized root/base metadata.

## Motivation

- **The cleanup loop remains repeatable**: the previous five batches each removed 10 warning-only findings without validator changes.
- **The next candidate JSON remains low-risk**: the selected rank `1` through `10` rows are all `root_base_match` candidates in `es`, `fr`, and `pt`.
- **Warning debt should keep moving downward**: this batch keeps the candidate queue actionable while preserving hard-error semantics.
- **Evidence-led tie handling remains important**: same-overrun candidates can display differently in CLI summaries, so this milestone follows the fresh candidate JSON rank order.

## Out of Scope

- **JA/KO/RU/AR cleanup** — these require stronger language review and stay out of this batch.
- **More than 10 metadata edits** — keep the batch auditable.
- **Validator behavior changes** — candidate export and TDK thresholds stay as-is.
- **Rendered metadata architecture changes** — source copy only.
- **Duplicate-key cleanup** — some locale files contain legacy duplicate slug blocks; this batch edits only the effective values surfaced by the validator.

## Key Design Constraints

1. **Edit both layers together**: every selected root/base pair must end with identical values.
2. **Stay within bounds**: Latin `seo_description` must be between `50` and `180` characters.
3. **Keep copy specific**: descriptions should mention the tool's actual job, not only privacy/free boilerplate.
4. **Measure before and after**: record the exact warning-count delta.
5. **Leave reports ignored**: `.planning/research/reports/` remains untracked.
