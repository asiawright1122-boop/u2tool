## Milestone Goal

继续使用 v0.0.32 的 TDK cleanup candidate export，完成第三组可审查的实际文案收敛：处理 fresh v0.0.35 candidate JSON 中 ranks `1` 到 `10` 的 `root_base_match`、拉丁语系、overlong `seo_description` 候选，同步更新 root/base 两层，把 warning-only TDK debt 从 `2772` 降到 `2762`。

This is another **bounded metadata cleanup** milestone. It should not redesign validators, change thresholds, or mass-edit multilingual copy. The expected outcome is a measured 10-warning reduction while preserving `0` hard errors and synchronized root/base metadata.

## Motivation

- **The cleanup loop is repeatable**: v0.0.33 and v0.0.34 each removed 10 warning-only findings without validator changes.
- **The next candidate JSON is still low-risk**: the selected rank `1` through `10` rows are all `root_base_match` candidates in `es`, `fr`, and `pt`.
- **Warning debt should keep moving downward**: this batch proves the candidate queue remains actionable after two prior cleanup passes.
- **Tie ordering must be evidence-led**: the CLI largest-example summary and candidate export can differ on same-overrun ties, so this milestone follows the fresh candidate JSON rank order.

## Out of Scope

- **JA/KO/RU/AR cleanup** — these require stronger language review and stay out of this batch.
- **More than 10 metadata edits** — keep the batch auditable.
- **Validator behavior changes** — candidate export and TDK thresholds stay as-is.
- **Rendered metadata architecture changes** — source copy only.
- **Duplicate-key cleanup** — some locale `base.json` files contain legacy duplicate slug blocks; this batch edits only the effective values surfaced by the validator.

## Key Design Constraints

1. **Edit both layers together**: every selected root/base pair must end with identical values.
2. **Stay within bounds**: Latin `seo_description` must be between `50` and `180` characters.
3. **Keep copy specific**: descriptions should mention the tool's actual job, not only privacy/free boilerplate.
4. **Measure before and after**: record the exact warning-count delta.
5. **Leave reports ignored**: `.planning/research/reports/` remains untracked.
