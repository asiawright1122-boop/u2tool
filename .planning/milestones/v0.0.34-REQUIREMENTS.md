# Requirements: v0.0.34 - TDK Cleanup Batch Two

## Milestone Goal

继续使用 v0.0.32 的 TDK cleanup candidate export，完成第二组可审查的实际文案收敛：处理新的前 10 个 `root_base_match`、拉丁语系、overlong `seo_description` 候选，同步更新 root/base 两层，把 warning-only TDK debt 从 `2782` 降到 `2772`。

This is a **bounded metadata cleanup** milestone. It should not redesign validators, change thresholds, or mass-edit multilingual copy. The expected outcome is another measured 10-warning reduction while preserving `0` hard errors and synchronized root/base metadata.

## Motivation

- **The candidate queue is proving useful**: v0.0.33 removed the first 10 candidates and left a fresh ranked backlog.
- **The next candidates remain low-risk**: the next top 10 entries are `root_base_match` candidates in `es` and `pt`.
- **Warning debt should keep moving downward**: this batch proves the cleanup process is repeatable without validator changes.
- **Copy quality still matters**: replacements should be local-language, topical, and within safe bounds instead of generic truncations.

## Out of Scope

- **JA/KO/RU/AR cleanup** — these require stronger language review and stay out of this batch.
- **More than 10 metadata edits** — keep the batch auditable.
- **Validator behavior changes** — candidate export and TDK thresholds stay as-is.
- **Rendered metadata architecture changes** — source copy only.

## Key Design Constraints

1. **Edit both layers together**: every selected root/base pair must end with identical values.
2. **Stay within bounds**: Latin `seo_description` must be between `50` and `180` characters.
3. **Keep copy specific**: descriptions should mention the tool's actual job, not only privacy/free boilerplate.
4. **Measure before and after**: record the exact warning-count delta.
5. **Leave reports ignored**: `.planning/research/reports/` remains untracked.
