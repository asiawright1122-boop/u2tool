# Requirements: v0.0.32 - TDK Cleanup Batch Planner

## Milestone Goal

把 v0.0.31 留下的 `2792` 条 TDK warning-only 优化债，推进成可分批审阅的 cleanup backlog：`validate:tdk-integrity` 继续保持硬错误 gate，同时能导出按超限程度排序、带 root/base 同步状态和当前值证据的候选清单，让后续多语言文案清理可以小批次、可复跑、可审查地进行。

This is a **TDK cleanup planning and release-health ergonomics** milestone. It should not mass-edit localized metadata copy. The work may extend the offline validator, add focused tests, update planning evidence, and emit a reviewable candidate JSON export under `.planning/research/reports/`.

## Motivation

- **Hard TDK errors are clear**: the current baseline remains `0` hard errors.
- **Warning debt is still large**: the latest measurement on 2026-06-27 is `2792` warning-only findings, including `seo_title=442`, `seo_description=2350`, `short=6`, and `long=2786`.
- **Manual cleanup needs a safer queue**: the top warning clusters include many non-English descriptions (`ja`, `ko`, `ru`, `fr`, `ar`) where blind truncation would risk copy quality.
- **The validator already has the right source truth**: v0.0.31 added full report output and warning taxonomy; v0.0.32 should add a candidate export on top of that rather than inventing a second scanner.

## Requirements

### TDK Cleanup Batch Planner (TDK-BP)

- [x] **TDK-BP-01** - **Fresh candidate baseline capture**: Planning evidence must record the current `validate:tdk-integrity` baseline accurately: `0` hard errors, `2792` warning-only findings, `seo_title=442`, `seo_description=2350`, `short=6`, `long=2786`, and the top locale/category hotspots.
- [x] **TDK-BP-02** - **Ranked cleanup candidate model**: The validator must expose pure candidate-building helpers that filter warning-only length findings by locale, field, and direction, then rank them by overrun size with stable tie-breakers.
- [x] **TDK-BP-03** - **Root/base source-layer metadata**: Cleanup candidates must include current value evidence plus root/base source-layer status (`root_base_match`, `root_base_mismatch`, `root_only`, `base_only`, or `missing`) and file paths where available.
- [x] **TDK-BP-04** - **Candidate export CLI**: `validate:tdk-integrity` must support `--candidates-path`, `--candidate-top`, `--candidate-locales`, `--candidate-fields`, and `--candidate-directions` without changing the default hard-fail or warning-only exit policy.
- [x] **TDK-BP-05** - **Focused automated tests**: Add focused tests for candidate ranking, filtering, export shape, source-layer sync metadata, and CLI parsing/validation.
- [x] **TDK-BP-06** - **Planning/testing doc alignment**: Update roadmap, state, phase evidence, and testing docs so the next cleanup operator sees the candidate export as the active TDK warning backlog handoff.

## Out of Scope

- **Mass multilingual copy rewriting** — this milestone exports reviewable candidates; actual content edits should stay in later bounded batches.
- **Changing TDK thresholds** — length bounds remain the v0.0.31 policy.
- **New online probes** — production drift checks remain owned by `validate:tdk-drift:online`.
- **Hard-fail policy changes** — missing metadata and placeholder leakage remain errors; length findings remain warning-only optimization debt.
- **Template or rendering architecture changes** — no route, page, or metadata rendering behavior changes are intended.

## Key Design Constraints

1. **Planner before cleanup**: create a trustworthy candidate list before touching more localized copy.
2. **Reviewable evidence**: each candidate must show the current value and source-layer status so reviewers know what file(s) need synchronized edits.
3. **Default gate stability**: ordinary `validate:tdk-integrity` runs must keep the same pass/fail semantics.
4. **Small-batch friendly**: filters should support locale-, field-, and direction-scoped follow-up batches.
5. **No duplicate scanner**: reuse the existing report findings as the candidate source.
