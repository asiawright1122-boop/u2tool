# Requirements: v0.0.33 - TDK Cleanup Batch One

## Milestone Goal

用 v0.0.32 新增的 TDK cleanup candidate export 完成第一组可审查的实际文案收敛：只处理前 10 个 `root_base_match`、拉丁语系、overlong `seo_description` 候选，同步更新 root/base 两层，证明候选导出可以安全驱动小批量 TDK warning 减量。

This is a **bounded metadata cleanup** milestone. It should not redesign validators, change length thresholds, or mass-edit multilingual copy. The expected outcome is a measured warning reduction from `2792` to `2782` while keeping hard errors at `0` and root/base metadata synchronized for every edited pair.

## Motivation

- **Candidate queue is ready**: v0.0.32 exports ranked candidates with source-layer status and current value evidence.
- **Top candidates are low-risk synchronized pairs**: the first 10 candidates are `root_base_match` entries in `es`, `fr`, and `pt`, so root/base can be edited together without resolving source-layer divergence.
- **Warning debt should now move downward**: the previous milestone made the queue reviewable; this milestone proves it can reduce the warning count in a small, auditable batch.
- **Copy quality still matters**: each replacement should stay topical, local-language, and within safe bounds instead of mechanically truncating text.

## Out of Scope

- **JA/KO/RU/AR cleanup** — these require stronger language review and stay out of this batch.
- **More than 10 metadata edits** — keep the batch auditable.
- **Validator behavior changes** — candidate export and TDK thresholds stay as-is.
- **Rendered metadata architecture changes** — source copy only.

## Key Design Constraints

1. **Edit both layers together**: every selected root/base pair must end with identical values.
2. **Stay within bounds**: Latin `seo_description` must be between `50` and `180` characters.
3. **Keep copy specific**: descriptions should mention the tool's actual job, not only privacy/free boilerplate.
4. **Measure before and after**: record the exact warning-count delta.
5. **Leave reports ignored**: `.planning/research/reports/` remains untracked.
