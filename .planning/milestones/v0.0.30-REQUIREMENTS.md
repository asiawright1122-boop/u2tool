# Requirements: v0.0.30 - Translation Warning Signal Reduction

## Milestone Goal

把当前 translation governance 从“硬错误已清零，但 warning-only 噪音过大”推进到一个更可操作的状态：重新量化并收敛 `validate:translation-corpus` 的 namespace drift 与 `validate:merge-chain-consistency` 的 duplicate-source overlap，让 release evidence 能区分真实新回归和历史噪音，同时保持现有 schema / coverage / resolved-divergence 硬门禁不放松。

This is a **translation-governance and validation-signal** milestone. It should not intentionally change rendered metadata, routing, or page templates. It may refine offline validation scripts, warning taxonomy, bounded duplicate-source cleanup, tests, and planning docs so translation warning surfaces become smaller and more trustworthy.

## Motivation

- **旧 backlog 叙事已经过期**：v0.0.23 审计里记录过的“17 missing split slugs”现在已经不再是当前事实。2026-06-24 的新实测显示 `validate:translation-corpus` 已经是 `Schema errors: 0`、`Coverage gaps: 0`，说明真实下一步不再是补缺文件。
- **现在剩下的是两大 warning-only 噪音面**：最新实测里，`validate:translation-corpus` 仍有 `325` 个 `group_key_drift` warning，而 `validate:merge-chain-consistency` 仍有 `15301` 个 duplicate support-key overlap warning；它们都不会阻断 release，但已经大到掩盖新增异常。
- **warning 分布高度集中，说明这不是随机脏数据**：`325` 个 namespace warning 里有 `296` 个来自 `zh`；`15301` 个 overlap warning 里有 `15034` 个是 `root`-only duplicate source。这提示我们下一步应该优先做 warning signal reduction，而不是继续泛化新探测器。
- **release evidence 需要恢复可读性**：当前硬错误全绿，但 warning 面积过大，导致 release 证据很难快速回答“这次是不是引入了新漂移”。下一阶段要让 warning 输出重新有辨识度。

## Out of Scope

- **Broad catalog-wide translation rewriting** — this milestone is about warning signal quality first, not rewriting every tool copy surface.
- **New production or network-dependent probes** — the scope stays offline and deterministic.
- **Weakening hard gates** — schema errors, coverage gaps, and resolved divergences must remain strict.
- **User-facing rendering, routing, or metadata changes** — only change them if a bounded warning cleanup truly requires it, and keep the milestone centered on governance signal.

## Key Design Constraints

1. **Current facts beat inherited backlog**: Do not plan around stale evidence once a fresh local run shows the repo state has changed.
2. **Signal reduction, not gate weakening**: The goal is to make warnings smaller or better classified, not to hide them by downgrading errors.
3. **Prefer concentrated wins**: Attack the hotspots that dominate counts first (`zh` namespace drift, root-layer overlap noise) before chasing scattered one-offs.
4. **Mechanically safe cleanup only**: If a cleanup pass touches message files, prefer dead duplicate-source removal or clear structural normalization over subjective copy rewrites.
5. **Readable evidence matters**: Reports and docs should let the next operator see whether warning counts changed for structural reasons or because of a fresh regression.
