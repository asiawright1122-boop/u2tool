# Requirements: v0.0.31 - TDK Compliance Warning Signal Reduction

## Milestone Goal

把 `validate:tdk-integrity` 从“硬错误可用，但 warning-only 输出过长”推进到一个可审阅的 release-health 信号面：保留缺失元数据和 placeholder 泄漏的 hard-fail 语义，同时让 `2802` 条 TDK length/style warning 能按 locale、field、category、slug 和超限程度汇总，并完成一个小范围、可验证的元数据长度收敛批次。

This is a **TDK governance and release-health signal** milestone. It should not redesign rendered metadata architecture, add new network probes, or rewrite the whole catalog. The work may refine the offline validator, add tests, update planning evidence, and trim a small set of high-overrun `seo_description` entries where the change is local, topical, and easy to verify.

## Motivation

- **Translation warning channels are now clear**: v0.0.30 follow-ups reduced both `validate:translation-corpus` namespace warnings and `validate:merge-chain-consistency` overlap warnings to `0`, so the next large release-health noise source moved to TDK compliance warnings.
- **Current TDK warning output is too large to review**: `validate:tdk-integrity` still reports `2802` warning-only length/style suggestions, previously as a full flat list. That makes `qa:seo-governance` noisy even though hard errors remain clear.
- **The warning surface is concentrated**: fresh measurement on 2026-06-26 shows `2360/2802` warnings are `seo_description`, `2796/2802` are overlong, and the biggest locale hotspots are `ja=498`, `ko=427`, `ru=350`, `fr=309`, `ar=298`, `es=268`, `de=236`, `zh=205`, `pt=184`, and `en=27`.
- **A small content slice can prove the workflow**: the largest overrun entries are long boilerplate descriptions in root/base metadata layers. A top-10 trim can lower warning count without broad subjective rewriting.

## Requirements

### TDK Compliance Warning Signal Reduction (TDK-W)

- [x] **TDK-W-01** - **Fresh warning baseline capture**: Planning docs must record the current `validate:tdk-integrity` warning baseline accurately: `0` hard errors, `2802` warning-only findings, `seo_title=442`, `seo_description=2360`, `short=6`, `long=2796`, with locale/category hotspots.
- [x] **TDK-W-02** - **Validator CLI ergonomics**: `validate:tdk-integrity` must support `--help`, `--report-path` / `--json-out`, and `--top` so release runs can print summaries while preserving full JSON detail under `.planning/research/reports/`.
- [x] **TDK-W-03** - **Warning summary taxonomy**: The validator must summarize warnings by field, direction, top locales, top categories, top locale/field pairs, top slugs, and largest over-limit examples without changing hard-fail policy.
- [x] **TDK-W-04** - **Focused automated tests**: Add focused tests for per-tool TDK validation, hard errors, forbidden placeholders, CJK length warning metadata, report aggregation, and CLI parsing.
- [x] **TDK-W-05** - **Bounded top-overrun cleanup**: Trim the top 10 overlong `seo_description` entries in `es`, `pt`, and `fr` root/base metadata layers, preserving topic specificity and keeping root/base descriptions synchronized.
- [x] **TDK-W-06** - **Backlog and testing doc alignment**: Update planning/testing evidence so the next operator sees TDK warning count reduction as the active release-health line, not translation warning cleanup.

## Out of Scope

- **Full catalog TDK rewrite** — this milestone only proves the signal and completes a small content slice.
- **New online probes** — `validate:tdk-drift:online` already owns production drift checks; this work remains offline.
- **Changing hard-fail policy** — missing metadata and forbidden placeholders remain errors; length warnings remain non-blocking optimization debt.
- **Template or rendering architecture changes** — no page-template, routing, or metadata rendering changes are intended.

## Key Design Constraints

1. **Evidence before cleanup**: capture and summarize the baseline before editing content.
2. **Signal first, then a small slice**: improve the validator output before trimming metadata copy.
3. **No gate weakening**: lower console noise without hiding hard errors or dropping JSON detail.
4. **Keep metadata topical**: shortened descriptions must still say what the tool actually does.
5. **Preserve layer consistency**: when root and base carry the same metadata value, update both together.
