# Requirements: v0.0.25 - Cluster Card / Tool Island Commonality Extraction

## Milestone Goal

从 8 个 `src/lib/*-cluster.ts` 数据文件和 16 个 `*ClusterCard.astro` / `*ClusterSection.astro` 组件中抽取共性，建立统一的类型模块（`tool-cluster-types.ts`）、工厂模块（`tool-cluster-factory.ts`）和统一组件（`ToolClusterCard.astro` / `ToolClusterSection.astro`），消除 lib/component 层的 8 倍对称性。同时简化 `[slug].astro` 中 `CLUSTER_BLOCKS` 的类型定义并修复遗留 bug。

This is a **refactor-only** milestone: it changes code structure, not behavior. No SEO output, structured data, hreflang, canonical, OG/Twitter metadata, breadcrumb, FAQ, cluster card rendering, or translation loading logic may change.

## Motivation

- **8 倍对称性已到临界点**：8 个 `*-cluster.ts` 文件各自定义相同的 group/copy/path 结构，16 个 `*ClusterCard.astro` + `*ClusterSection.astro` 组件逻辑几乎一致。新增第 9 个 cluster 需要同步改 ~6 处，极易遗漏。
- **v0.0.24 的延续**：v0.0.24 在页面层建立了 `CLUSTER_BLOCKS` 数组 + 单一 `.map` 渲染循环。v0.0.25 在 lib/component 层做进一步抽象，使 `CLUSTER_BLOCKS` 的类型定义可引用共享接口而非内联匿名类型。
- **遗留 bug**：Phase 84 统一组件后，`[slug].astro` 模板仍解构 `Card`（旧的 per-cluster 判别器字段），实际应为统一的 `ToolClusterCard`。这是一个运行时错误（`Card` = `undefined`）。

## Requirements

### Shared Cluster Types & Factory (SCT)

- [x] **SCT-01** - **Shared type module (`tool-cluster-types.ts`)**: 新建 `src/lib/tool-cluster-types.ts`，导出 `ToolClusterItem`、`ToolClusterGroup<GroupId>`、`ToolClusterCopy`、`ToolClusterGroupDef<GroupId>`、`ClusterColorTheme`、`ToolClusterBlock` 共 6 个共享类型。8 个 `*-cluster.ts` 数据文件的 `Group`/`Copy` union 类型改为 `ToolClusterGroup<string>` / `ToolClusterCopy` 的 re-export。
- [x] **SCT-02** - **Shared factory module (`tool-cluster-factory.ts`)**: 新建 `src/lib/tool-cluster-factory.ts`，导出 4 个泛型 builder：`buildClusterGroupForTool()`（按 slug 找子组）、`buildClusterGroups()`（构建全部分组 + 本地化工具列表）、`resolveClusterCopy()`（本地化 copy + 英文回退）、`buildClusterItemList()`（构建工具项列表）。8 个 `*-cluster.ts` 内部调用改为委托 factory。
- [x] **SCT-03** - **Unit tests**: 新建 `src/lib/tool-cluster-factory.test.ts`，覆盖 factory 的 4 个 builder + `buildClusterCollectionData()`（JSON-LD 结构化数据 builder）。
- [x] **SCT-04** - **CLUSTER_BLOCKS type simplification**: `[slug].astro` 中 `CLUSTER_BLOCKS` 的内联匿名类型改为引用共享 `ToolClusterBlock` 接口。移除 16 个不再使用的 per-cluster `type` import（如 `type ChartToolClusterGroup`、`type ChartToolClusterCopy` 等）。

### Unified Cluster Components (UCC)

- [x] **UCC-01** - **Unified ToolClusterCard.astro**: 新建 `src/components/tools/ToolClusterCard.astro`，接收 `group`、`copy`、`currentSlug`、`clusterHref`、`theme`、`dataPrefix` props，替代 8 个 per-cluster Card 组件。输出结构与旧组件一致。
- [x] **UCC-02** - **Unified ToolClusterSection.astro**: 新建 `src/components/tools/ToolClusterSection.astro`，接收 `groups`、`copy`、`locale`、`dataPrefix` props，替代 8 个 per-cluster Section 组件。输出结构与旧组件一致。
- [x] **UCC-03** - **Delete old components**: 删除 16 个旧文件（8 Card + 8 Section）。
- [x] **UCC-04** - **Update consumers**: 更新 `[slug].astro`、`index.astro`、`tools.astro`、`[category].astro` 的 import 指向统一组件。

### Template Bug Fix (TBF)

- [x] **TBF-01** - **Fix Card discriminator bug**: `[slug].astro` 模板中 `CLUSTER_BLOCKS.map(({ group, Card, ... }) => <Card .../>)` 的 `Card` 解构是 Phase 84 前的遗留判别器字段（已不存在），运行时为 `undefined`。改为直接使用 `<ToolClusterCard .../>`。

## Out of Scope

- **修改任何 `src/messages/` 消息文件** —— 与 v0.0.22+ 的 detection/refactor-only 纪律一致。
- **改变任何渲染行为** —— SEO 输出、structured data、hreflang、canonical、OG/Twitter、breadcrumb、FAQ、cluster card 渲染、translation loading、ToolWrapper 契约，全部必须保持不变。
- **性能优化** —— 不以减小 bundle size 或提升 LCP 为目标。

## Key Design Constraints

1. **Behavior-preserving（行为保持）**: 重构后的页面渲染输出必须与重构前一致。任何无法通过验证的行为差异都视为失败。
2. **渐进式抽象**: 先抽取类型（Phase 83），再统一组件（Phase 84），最后简化调用点（Phase 85）。每阶段独立可验证。
3. **不改外部契约**: 8 个 `*-cluster.ts` 的公开 API（`buildXxxClusterGroupForTool`、`getXxxClusterCopy`、`xxxClusterPath`）签名不变，内部实现改为委托 factory。
