# Requirements: v0.0.27 - Production QA Closure

## Milestone Goal

把 `qa:production` 从“很长的一串命令”升级为可重复、可解释、可交接的 release checklist：明确本机/CI 前置条件、命令顺序、环境阻塞分类、失败证据标准，以及哪些 gate 是发布阻塞、哪些是 warning-only 噪音。

This is a **release-governance** milestone. It should not change user-facing product behavior, SEO output, translation content, or routing. It may add or update scripts/docs that make the existing production QA chain easier to run and interpret.

## Motivation

- **v0.0.26 暴露了 release 操作风险**：render contract gate 失败后，如果命令用换行裸跑，shell 会继续执行 `git commit`。v0.0.27 要把这种“人工流程漏洞”收进 checklist / wrapper / docs。
- **本地与 Codex 沙箱能力不同**：Codex 不能可靠 bind/listen/fetch localhost；本机终端可以。需要把“环境不可达”与“代码回归”区分清楚。
- **`qa:production` 太长且不透明**：需要把关键子链拆成阶段、记录证据格式，并说明失败时下一步该查哪里。
- **warning 噪音不能混淆发布状态**：translation namespace warnings、merge-chain overlap warnings 当前是 warning-only；发布 checklist 必须明确它们不是 v0.0.27 的修复范围。

## Requirements

### Production QA Closure (PQC)

- [ ] **PQC-01** - **QA chain inventory**: Document the current `qa:production` command chain in execution order, grouping gates by purpose: build/type safety, SEO governance, runtime integrity, rendered HTML/SSR, sitemap/routes, i18n/metadata, and edge simulation.
- [ ] **PQC-02** - **Environment preflight checklist**: Define the required local/CI environment before running SSR-backed gates: install state, `.env.local`, Cloudflare/Astro adapter constraints, local SSR startup command, reachable `FETCH_BASE_URL`, and expected `curl -I` probe result.
- [ ] **PQC-03** - **Failure taxonomy**: Classify failures into at least four buckets: code regression, content/data drift, environment/network blocker, and warning-only hygiene debt. Each bucket must include examples from current validators.
- [ ] **PQC-04** - **Guarded release command recipe**: Provide copy-paste-safe command recipes that use `&&` or a small wrapper so failed validation cannot be followed by accidental `git commit` / `git push`.
- [ ] **PQC-05** - **Evidence log format**: Define the minimal release evidence to capture before closing a milestone: commands, pass/fail counts, warning-only counts, local SSR URL, commit SHA, branch state, and known skipped gates.
- [ ] **PQC-06** - **Phase 87 validation pass**: Run and record the focused gates that can be verified in the current environment: render contract against a reachable SSR server, translation corpus, merge-chain consistency, TDK drift, and focused Vitest coverage. If full `qa:production` cannot run in Codex, document that as environment-limited and include the exact runnable local command.

## Out of Scope

- **Fixing all namespace / overlap warnings** — warning reduction belongs to a later content-governance milestone.
- **Changing product rendering or SEO content** — v0.0.27 is about release QA process, not user-facing output.
- **Replacing `qa:production` wholesale** — this milestone may wrap or document it, but should not rebuild the entire validation system.
- **Production-only metadata drift baseline** — `validate:tdk-drift:online` remains a candidate follow-up unless needed as evidence for this checklist.

## Key Design Constraints

1. **Evidence before claims**: Do not mark a gate as pass without fresh command output and exit-code interpretation.
2. **Environment-aware, not environment-weakened**: Localhost/Cloudflare sandbox blockers should be classified clearly, but normal local/CI gates stay strict.
3. **Copy-paste safety**: Commands intended for release use must prevent validation failure from falling through into commit/push.
4. **Small docs-first milestone**: Prefer clear docs and small wrappers over broad script refactors.
5. **Warning-only clarity**: Existing warning-only debt must be visible without blocking release closure.
