# Requirements: v0.0.28 - Traceability Contract Restoration

## Milestone Goal

恢复 `planning:traceability` 的真实审计价值：让它重新读懂当前的 `REQUIREMENTS.md` / `ROADMAP.md` / phase evidence 结构，生成非空、可验证、能指出缺口的 traceability report，并重新成为 `verify:production` 里可信的一环。

This is a **planning-and-release-governance** milestone. It should not change user-facing product behavior, tool rendering, SEO output, translation content, or routing. It may update planning scripts, generated reports, tests, and planning docs so requirement coverage is auditable again.

## Motivation

- **当前 traceability gate 实际失效**：`npm run planning:traceability` 退出 0，但生成的 [TRACEABILITY.md](/Users/kaka/Dev/u2tool/.planning/TRACEABILITY.md) 仍然显示 `Milestone: Unknown milestone`、`Total requirements: 0`、空的 phase/requirement coverage。它现在更像“假绿灯”。
- **问题已被历史明确点名**：v0.0.23 里已经记录过 parser regex 过时，当前 generator 仍然在用旧格式假设（`**Milestone:**`、`### Phase N:`、`- [x] ID: title`），和现在的 planning 文档结构不匹配。
- **它挂在 canonical release path 上**：`verify:production` 仍然调用 `planning:traceability`。如果 traceability 永远是空报告，release-health 就缺了一块真正的可追溯性证据。
- **这是小而硬的基础设施修复**：比直接清 warning 噪音更划算，也比做新的 online baseline 更贴近当前 repo 的明确缺口。

## Requirements

### Traceability Contract Restoration (TCR)

- [x] **TCR-01** - **Current-format parser support**: Update the traceability generator so it can parse the current planning document shape: active milestone headings, requirement bullets like `- [ ] **ID** - title`, traceability tables, and phase-plan sections such as `- [x] **Phase 87** - Name`.
- [x] **TCR-02** - **Non-empty coverage report**: `npm run planning:traceability` must produce a report with the active milestone name, non-zero requirement count, mapped phase coverage, and meaningful gaps when mappings/evidence are missing.
- [x] **TCR-03** - **Evidence file discovery refresh**: The generator must discover evidence from the actual planning artifacts used now (`*-SUMMARY.md`, milestone audits, and any current phase evidence docs that are intentionally tracked), instead of only the older summary naming pattern.
- [x] **TCR-04** - **Gap semantics**: The report must distinguish at least these cases: unmapped requirement, completed requirement missing evidence, planned-but-incomplete phase mapping, and no-gap success. It should stop claiming “No traceability gaps detected” when coverage is actually empty.
- [x] **TCR-05** - **Focused tests**: Add or update automated tests for the traceability parser/reporter covering the current roadmap/requirements format and at least one regression fixture where the old parser would have returned `Unknown milestone` and `0` requirements.
- [x] **TCR-06** - **Canonical verification proof**: Run `npm run planning:traceability` after the fix, capture the resulting report state, and record it in planning docs so `verify:production` regains trustworthy traceability evidence.

## Out of Scope

- **Reducing translation namespace or merge-overlap warnings** — those remain valid later candidates, but not the focus of v0.0.28.
- **User-facing rendering / SEO / routing changes** — this milestone is planning/reporting infrastructure only.
- **Rewriting the whole planning system** — keep the fix scoped to the current generator, its tests, and the minimum doc updates needed to verify it.
- **Manual one-off traceability tables** — the goal is to restore generated traceability, not to replace the broken generator with hand-maintained matrices again.

## Key Design Constraints

1. **Generated, not theatrical**: The fix must make `planning:traceability` truly useful, not just change wording around an empty report.
2. **Current-doc-format first**: Support the planning format actually used in this repo today before worrying about older shapes.
3. **Evidence-aware**: A completed requirement without discoverable evidence must surface as a gap, not disappear.
4. **Keep `verify:production` honest**: The traceability command must either produce meaningful coverage or fail loudly enough to reveal the problem.
5. **Scoped infrastructure fix**: Prefer parser/report improvements and focused tests over broad planning refactors.
